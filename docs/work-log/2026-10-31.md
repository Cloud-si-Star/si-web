# 2026-10-31 工作记录

## 销售 ETL 月度批处理

### 需求

- 保留销售处理接口及页面的单日执行能力。
- 为除种子数据外的日级销售 ETL 增加按月执行能力，月份由页面选择，后端按日历月份处理所有日期。
- 确保月度写入采用事务，失败时不留下部分月份的数据。
- 更新本次问题记录。

### 实现结果

- 新增 ODS、DWD、日销量汇总、日品类汇总四个 `monthly` 路由；`seeds` 不变。
- 月度路由根据 `YYYYMM` 自动计算当月天数，返回日期范围、逐日插入/丢弃统计和汇总数。
- 月度批处理调用服务时关闭逐日提交，全部日期成功后只提交一次；任一天或最终提交失败均回滚整月并记录错误。
- 月度批处理编排和四个任务专属月度方法统一放入 `analysis_service.py`；路由仅负责参数、响应模型及 HTTP 错误转换。
- 单日接口仍使用默认逐日提交行为。DWD 单日处理失败时补充回滚，避免失败事务残留。
- 月度区域汇总已有按 `YYYYMM` 处理整月的接口，因此页面继续调用原接口，不重复逐日执行该汇总。
- 页面在日级任务上增加“按月执行”按钮和月份选择；原单日按钮及日期选择保留。
- 后续将页面日任务拆分为相邻的单日行和月度行；每行仅显示对应日期/月份选择器与单个操作按钮，并统一操作按钮宽度。
- 月度请求超时设为 60 分钟，避免逐日批次运行时间超过单日接口超时。
- 更新后端路由清单与工作记录索引。
- 补充销售分析 service 中各 ETL 方法的用途、参数、返回值、事务行为和异常说明。
